# 智库 Skill (Librarian) — 法规与知识检索智能体

> ECO-Audit V3.0 五智能体架构 · Agent 5

---

## 1. Skill 名称和描述

**名称**: `eco-audit/librarian-skill`
**代号**: 智库 (Librarian)
**描述**: ECO-Audit 系统的"知识中枢"。在审计全过程中为哨兵、神探、专家三个智能体提供法规条款、历史案例、作弊特征库的实时检索服务。整合法律法规库（31 部法规/标准）、历史案例库、设备手册库和作弊特征库，支持关键词检索、规则反查、条款关联查询等多种检索模式。

**核心设计理念**: "知识即力量" —— 让每一个审计判定都有法可依、有据可查。

---

## 2. 触发条件

| 触发场景 | 示例 |
|----------|------|
| 其他 Agent 主动查询 | Sentry/Sherlock/Expert 发起法规检索请求 |
| 用户手动查询 | "查一下这条法规"、"有没有相关案例" |
| 规则执行需要法律映射 | 规则引擎触发时自动查询对应法律条款 |
| 案例参考需求 | 需要历史相似案例作为判定时参考 |
| 设备手册查询 | 需要特定品牌分析仪的技术参数或操作手册 |

## 3. 核心能力清单

### 3.1 法规条款检索
- **全文检索**: 按关键词搜索法规条款内容
- **规则反查**: 根据规则 ID（如 R001）查询对应法律条款
- **条款关联**: 查询某条法规关联的所有规则 ID
- **法规分类**: 按层级（国家法律/行政法规/部门规章/技术标准/地方标准）浏览
- **多法规交叉**: 同一行为涉及多部法规时的关联展示

### 3.2 历史案例库
- **案例检索**: 按违法行为类型、行业、地区检索历史案例
- **相似案例推荐**: 基于当前异常条目推荐相似历史案例
- **判罚统计**: 同类违法行为的处罚结果统计分析
- **案例摘要**: 典型案例的关键事实、证据链、判决结果

### 3.3 作弊特征库
- **YARA 规则库**: 已知作弊软件/后门程序的特征规则
- **作弊模式库**: 已确认的作弊手法及检测方法
- **设备特征库**: 各品牌分析仪的已知后门/隐藏菜单入口
- **特征库更新**: 自进化学习引擎提取的新模式（人工审核后入库）

### 3.4 设备手册库
- **分析仪手册**: ≥15 个主流品牌分析仪的技术手册
- **数采仪手册**: 主流数采仪的配置手册
- **协议规范**: HJ 212、Modbus、OPC-UA 等协议技术规范
- **验收基线**: 各型号设备的验收参数基线

### 3.5 检索 API
- RESTful API 接口供其他 Agent 调用
- 支持批量查询（单次最多 50 条）
- 响应时间 <100ms（本地索引）
- 支持离线运行（U 盘内置索引）

## 4. 工作流程

```
┌─────────────────────────────────────────────────────────┐
│                    智库工作流程                            │
├─────────────────────────────────────────────────────────┤
│                                                         │
│  Step 1: 知识库初始化（服务启动时）                         │
│  ├─ 加载法规知识库（legal_knowledge_base.json）             │
│  ├─ 加载案例库（case_database.json）                       │
│  ├─ 加载作弊特征库（cheat_signatures.yar）                  │
│  ├─ 加载设备手册库（device_manuals/）                       │
│  ├─ 构建全文检索索引                                       │
│  └─ 启动检索 API 服务（localhost:8080）                    │
│                                                         │
│  Step 2: 接收检索请求（持续监听）                            │
│  ├─ 接收其他 Agent 的 API 请求                             │
│  ├─ 解析请求类型（法规/案例/特征/手册）                      │
│  └─ 验证请求合法性                                         │
│                                                         │
│  Step 3: 执行检索                                        │
│  ├─ 全文检索: 倒排索引匹配                                 │
│  ├─ 规则反查: 规则ID → 法律条款直接映射                     │
│  ├─ 相似案例: 特征向量相似度计算                            │
│  └─ 特征匹配: YARA 规则扫描                                │
│                                                         │
│  Step 4: 返回检索结果                                     │
│  ├─ 格式化结果（JSON）                                     │
│  ├─ 附加相关性评分                                        │
│  └─ 记录检索日志（用于统计优化）                             │
│                                                         │
│  Step 5: 知识库更新（异步，管理员触发）                       │
│  ├─ 接收自进化学习引擎提交的新模式                          │
│  ├─ 人工审核                                             │
│  └─ 更新索引并重新加载                                     │
│                                                         │
│  ⚡ 响应时间: <100ms（单条查询）                            │
│  📦 离线运行: 全部数据存储在 U 盘本地                        │
└─────────────────────────────────────────────────────────┘
```

## 9. 与其他智能体的协作关系

```
                    ┌── 法规查询 ──→ Librarian (智库) ←── 案例查询 ──┐
                    │                                                   │
Guardian (门神) ──→ Sentry (哨兵) ──→ Sherlock (神探) ──→ Expert (专家)
                    │                    │                    │
                    └── 法规查询 ────────┘                    └── 案例查询 ──→ 最终报告
```

- **服务对象**: 哨兵、神探、专家三个智能体
- **查询类型**: 法规映射（规则 → 法律条款）、案例推荐、特征匹配、设备手册
- **数据流向**: 单向服务 —— 智库只提供查询，不主动发起请求

---

## 10. 注意事项

1. **离线运行**: 所有知识库必须完整存储在 U 盘本地，不依赖网络连接
2. **索引性能**: 法规库和案例库需预构建全文检索索引，确保 <100ms 响应
3. **版本管理**: 法规库需记录版本号和生效日期，确保引用的是现行有效版本
4. **审核机制**: 自进化学习引擎提交的新模式必须经过人工审核后方可入库
5. **容量规划**: U 盘需预留 ≥4GB 空间用于知识库存储（含设备手册）
