# EcoMind OS 执行审计标准 — 主智能体自检

> 用途：每次 EcoMind 完成任务后，按此标准逐项核查
> 适配自 Claude Code SpecCoding Audit 标准

---

## 审计 Checklist（每项任务完成后必须验证）

### 数据层（必须全部满足）
- [ ] 环境数据来源已标注（省厅实时 / 基准回退 / 降级模拟）
- [ ] 数据时间戳可见，与实际查询时间偏差 < 10分钟
- [ ] 如使用基准回退数据，已明确标注「⚠️ 当前使用基准数据，非实时监测值」
- [ ] PM2.5/PM10/O3/NO2/SO2/CO 六项指标完整，无遗漏
- [ ] 县级市数据已标注「数据来自所属地级市监测站」

### 法规层（必须全部满足）
- [ ] 每个合规判断至少引用 1 条法规原文（含法规名 + 条款号）
- [ ] 法规引用不张冠李戴（大气问题不引用水污染防治法）
- [ ] 未擅自编造不存在的法规条款
- [ ] 处罚建议已标注裁量基准来源
- [ ] L3 级别结论已附安全声明

### 输出层（必须全部满足）
- [ ] 输出遵循对应格式模板（监测报告/合规分析/执法文书）
- [ ] 无占位文字（如 "[待补充]"、"TODO"）
- [ ] 中文表述专业、条理清晰
- [ ] 数值单位正确（μg/m³、mg/m³ 不混用）
- [ ] 图表数据与文字描述一致

### 工程层（代码变更时适用）
- [ ] `git branch feature/<name>` — 独立分支
- [ ] 至少 1 个 commit（含实际代码变更）
- [ ] `git merge` 回主分支
- [ ] `spec/tasks.md` 对应项标记 [x]
- [ ] `spec/devlog.md` 追加一条记录

### 代码层（代码变更时适用）
- [ ] 前端组件存在且非 mock/占位
- [ ] 后端路由已注册到 main.py
- [ ] 后端 service 有实际业务逻辑（非 pass）
- [ ] 前后端 API 对接完成（非 mock 数据）
- [ ] TypeScript 类型定义完整

### 安全层（全部任务适用）
- [ ] 无泄露内部 API Key 或敏感配置
- [ ] L3 执法建议已标注人工审核要求
- [ ] 公众查询不暴露内部数据

---

## 严禁行为

- ❌ 不接受「环境数据看起来合理」— 必须来自实际 API 或明确标注回退
- ❌ 不接受「法条应该差不多」— 必须引用具体条款编号
- ❌ 不接受「报告格式随意」— 必须遵循对应模板
- ❌ 不接受「数据没连上就用随机数」— 必须明确标注降级状态
- ❌ 不接受「0 commit 声称完成任务」
- ❌ 不接受「声称有测试但无测试文件」
- ❌ 不接受「文档很好看，代码全是骨架」
- ❌ 不接受 **凭空编造环境数据** — 这是底线中的底线

---

## 审计流程

```
EcoMind 声称完成
  → 打开本 audit checklist
  → 逐项核实数据/法规/输出/安全四层
  → 全部通过 → 归档 + 追加 devlog
  → 任一项不通过 → 驳回重做 + 标注未通过项
```
