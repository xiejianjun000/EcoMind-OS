# EcoMind OS vs WorkBuddy — 三区 UI 差距对比分析

> 生成日期：2026-06-08  
> 分析基于：EcoMind OS 本地源码 + WorkBuddy 官方文档 + 腾讯云技术文章

---

## 一、左边栏（Sidebar）对比

### 1.1 信息架构对比

| 维度 | EcoMind OS | WorkBuddy |
|------|-----------|-----------|
| **一级入口数** | 6 个可展开区（专家/技能/连接器/资料库/自动化/工作空间） | 3 个（新建任务/技能中心/记忆管理） |
| **核心心智模型** | "专家驱动"——先选专家，再开始对话 | "任务驱动"——先描述任务，AI 自主规划 |
| **导航层级** | 三级：区 > 列表 > 详情 | 两级：入口 > 任务列表 |
| **信息密度** | 高（12 专家 + 4 技能 + 3 连接器 + 3 资料 + 3 自动化 + N 会话） | 低（仅任务列表 + 3 入口） |

### 1.2 EcoMind OS 左边栏已有功能（源码验证）

```
sidebar.tsx 结构：
├── Header: "EcoMind OS" + 搜索框
├── 新建会话按钮
├── ScrollArea:
│   ├── 专家区 (12 个，ExpertList 组件)
│   │   ├── GAIA 生态主控 (online)
│   │   ├── 环境监测专家 (online)
│   │   ├── 执法监察专家 (online)
│   │   ├── 环评审批专家 (busy)
│   │   ├── 生物多样性专家 (offline)
│   │   ├── 排污许可专家 (online)
│   │   ├── 生态修复专家 (online)
│   │   ├── 应急管理专家 (offline)
│   │   ├── 生态督察专家 (online)
│   │   ├── 碳排放专家 (online)
│   │   ├── 公众服务专家 (online)
│   │   └── 水资源专家 (offline)
│   ├── 技能区 (3D地图分析/报告生成/合规校验/遥感解译)
│   ├── 连接器区 (监测站点/IoT传感器/卫星遥感)
│   ├── 资料库区 (腾讯文档/ima知识库/乐享知识库)
│   ├── 自动化区 (定时巡检/异常告警/自动报告)
│   └── 工作空间区 (SessionList)
└── Footer: 主题切换 + 设置 + 团队成员头像
```

**关键发现**：
- 专家列表**硬编码**在 `expert-list.tsx`，未接入 `expertStore.ts`——数据来源不一致
- 会话列表 `session-list.tsx` 也是硬编码 mock 数据
- `SkillMenu.tsx` 使用 Ant Design 的 Tooltip，而 `sidebar.tsx` 使用 shadcn/ui——**同一组件内 UI 库混用**

### 1.3 WorkBuddy 有而 EcoMind 缺失的功能

| 缺失功能 | WorkBuddy 实现 | EcoMind 需补充 |
|----------|---------------|----------------|
| **文件夹分组** | 任务按文件夹分组管理 | 会话仅有平铺列表，无分组/归档 |
| **拖拽排序** | 支持拖拽重新排列 | 无拖拽交互 |
| **快捷模板** | [写代码] [修Bug] [读文件] [调API] | 无模板入口，仅"新建会话" |
| **智能预填充** | 输入指令→自动匹配技能+预填上下文 | 技能区为静态列表，无动态匹配 |
| **技能动态加载** | 非高频功能需关键词触发才加载 | 所有区始终展开，信息过载 |
| **记忆管理入口** | 一级入口：记忆管理 | 无对应入口 |

### 1.4 设计差距评估

**问题 1：信息架构过重**
EcoMind 的 6 区展开式设计，首次打开就显示大量信息。WorkBuddy 只保留 3 个入口，其余按需展开。对于政务场景，用户可能不需要看到"自动化"区的 3 个选项始终占据空间。

**问题 2：专家列表与专家选择器割裂**
左边栏的专家列表（`expert-list.tsx`）和输入框的专家下拉（`ChatInput.tsx` 的 `Select`）是两套独立数据源。左边栏点击专家无法自动切换对话专家，缺少联动。

**建议**：
- 合并左边栏 6 区为 4 区：专家 + 技能(含连接器) + 会话 + 设置
- 点击专家列表项自动切换 ChatInput 的 activeExpert
- 增加"快捷模板"区：[环评预检] [水质分析] [合规校验] [应急响应]

## 二、中间对话框 + 右边栏对比

### 2.1 中间对话框（Chat Area）对比

| 维度 | EcoMind OS | WorkBuddy |
|------|-----------|-----------|
| **消息气泡 UI 库** | 双版本并存：Ant Design（MessageBubble.tsx）+ shadcn/ui（Chat/index.tsx 内联版） | 统一设计系统 |
| **思维链展示** | ThinkingBlock 可折叠，`<SafetyOutlined>` 图标 + "推理过程" | 无对应（开发者场景不需要） |
| **幻觉风险** | 彩色 Badge（红>50%/黄>20%/绿<20%） | 无对应 |
| **代码展示** | 纯文本 `whitespace-pre-wrap` | 语法高亮 + 三态按钮（复制/运行/调试） |
| **工具调用展示** | `toolsUsed` 数组→灰色标签列表 | 代码执行→内嵌终端 |
| **内联组件** | 8 种类型（chart/map/table/approval/alert/document/task/image） | 文件变更 diff 视图 |
| **流式输出** | `isStreaming` + 光标闪烁 `animate-pulse` | Agent 存活检测（3态：运行中/已停止/无进程） |
| **消息操作** | 复制/点赞/点踩/朗读（hover 显示） | 复制/运行/调试（代码块右下角常驻） |

### 2.2 EcoMind OS 对话区详细分析（源码级）

**双版本 MessageBubble 问题**：

```
版本 A：Chat/components/MessageBubble.tsx
  - 使用 Ant Design（Avatar, Tooltip, Button, Badge）
  - 支持：思维链折叠 + 幻觉风险 + 工具标签 + 流式光标
  - 暗色模式：内联 style 变量（textColor, mutedColor, aiBg...）

版本 B：Chat/index.tsx 内联的 MessageBubble 函数
  - 使用 shadcn/ui（cn(), Avatar, Badge）
  - 支持：专家头像 + 参与者列表 + 点赞/复制/朗读
  - 暗色模式：Tailwind class（bg-primary, text-primary-foreground, bg-muted）
```

**两版气泡并存**——实际渲染哪个取决于路由挂载的是哪个组件。这是一个**架构债务**。

**EcoMind 独有而 WorkBuddy 没有的**：
- 思维链折叠展示（政务场景需要审计推理过程）
- 幻觉风险 Badge（EcoVerifyAdapter 六层验证的结果可视化）
- 安全等级标签（L1/L2/L3 对应 GovMCP 三级审批）
- 8 种内联组件（chart/map/table/approval/alert/document/task/image）——政务场景的富内容展示

### 2.3 右边栏（Result/Artifact Panel）对比

| 维度 | EcoMind OS | WorkBuddy |
|------|-----------|-----------|
| **Tab 数量** | 3 Tab（产物/任务/通知） | 4 视图（产物/全部文件/变更/预览） |
| **产物类型** | 7 种（document/chart/map/table/image/video/report） | 文件级（任意类型） |
| **任务面板** | 独立 Tab：进度条 + 状态图标 + 错误信息 | 无独立 Tab（集成在对话区） |
| **通知面板** | 独立 Tab：5 种类型 × 4 级严重度 + 已读/未读 | 无对应（通过 Agent 状态指示器替代） |
| **文件预览** | ArtifactList 仅列表，无内嵌预览 | 4 视图含实时预览 |
| **变更追踪** | 无 | git diff 风格变更视图 |
| **Agent 状态** | 无 | 3 态存活检测（alive/dead/null） |
| **折叠模式** | 40px 图标栏（3 图标 + 未读 Badge） | 可通过标题栏按钮展开/收起 |

### 2.4 EcoMind 右边栏详细分析（源码级）

```
ArtifactPanel 结构：
├── 折叠态 (40px):
│   ├── 展开按钮 (DoubleLeftOutlined)
│   ├── 产物图标 (FileTextOutlined)
│   ├── 任务图标 (CheckSquareOutlined)
│   └── 通知图标 (BellOutlined) + 未读数 Badge
└── 展开态 (320px):
    ├── Tab Header: 产物 | 任务 | 通知
    ├── 折叠按钮 (DoubleRightOutlined)
    └── Tab Content:
        ├── ArtifactList (7 种类型，图标+颜色映射)
        ├── TaskList (5 种状态图标 + 进度条)
        └── NotificationList (5 种类型 × 4 级严重度)
```

**WorkBuddy 独有功能**：
1. **全部文件视图**——展示任务关联的所有文件，以树形结构浏览
2. **变更视图**——git diff 风格，红绿高亮文件修改
3. **实时预览**——在右侧面板直接预览生成的 HTML/PDF/图片
4. **Agent 存活检测**——基于 OS 级进程检查，显示"Agent 正在运行"/"Agent 已停止"

**EcoMind 独有功能**：
1. **通知面板**——5 种类型（审批/安全/系统/任务/工作流），WorkBuddy 无独立通知区
2. **审批通知**——含审批流步骤、当前环节、请求人信息（政务场景核心需求）
3. **安全通知**——安全事件级别（low/medium/high/critical）

### 2.5 设计差距评估

**问题 1：缺少文件预览能力**
EcoMind 右边栏的 ArtifactList 只有列表视图，没有内嵌预览。对于政务场景生成的报告、图表，用户需要点击才能查看——WorkBuddy 在同一面板直接渲染预览。

**问题 2：缺少变更追踪**
WorkBuddy 的"变更"视图可以展示 AI 对文件/数据的修改记录。EcoMind 在政务场景中更需要审计追踪——谁改了什么、什么时候改的。

**问题 3：Agent 状态不透明**
EcoMind 用 `isLoading` 布尔值 + 流式光标判断状态，缺少 WorkBuddy 的进程级存活检测。如果 Agent 崩溃了，EcoMind 用户看到的是无限加载光标。

**建议**：
- 右边栏增加"预览"Tab，用 iframe 渲染 HTML 报告或图片
- 产物列表增加"变更记录"子视图
- 实现 Agent 存活检测：WebSocket 心跳 + 进程状态回传

## 三、下端对话输入框（Input Area）对比

### 3.1 功能对比

| 维度 | EcoMind OS | WorkBuddy |
|------|-----------|-----------|
| **核心选择器** | 专家下拉（Ant Select，140px 宽） | AI 模型选择器（多模型切换） |
| **快捷操作** | 4 按钮：技能/工具/连接器/资料库 | 快捷模板：[写代码] [修Bug] [读文件] [调API] |
| **附件上传** | PaperClip 图标按钮 | 支持文件拖拽 + 粘贴 |
| **输入控件** | Ant Input.TextArea (autoSize 1-6行) | 自然语言输入框 |
| **发送按钮** | 绿色圆形 (#52c41a)，含 LoadingOutlined | 发送按钮 |
| **安全信息** | L2·需确认 Badge | 无对应 |
| **模型信息** | 无 | 底部环境指纹（Node/npm/Git 版本） |
| **智能提示** | 无 | 环境缺失→替代方案提示 |

### 3.2 EcoMind 输入区详细分析（源码级）

**双版本问题再次出现**：

```
版本 A：Chat/components/ChatInput.tsx (Ant Design 版)
  ├── 专家 Select (borderless, 140px)
  ├── 3 文字按钮: 技能 / 连接器 / 资料库 (Ant Button type="text")
  ├── 安全等级标签 (右对齐): "当前权限: L2 · 需确认"
  ├── 输入区: 圆角容器 + PaperClip + Ant TextArea (borderless)
  └── 发送按钮: 绿色圆形 (#52c41a) + SendOutlined/LoadingOutlined

版本 B：Chat/index.tsx 内联的输入区 (shadcn/ui 版)
  ├── 专家 Select (shadcn, 180px)
  ├── 4 图标按钮: Sparkles/Wrench/Plug/BookOpen (shadcn Button variant="outline")
  ├── 输入区: shadcn Textarea (min-h-[60px]) + Paperclip 按钮
  ├── 发送按钮: 文字按钮 "发送" + Send 图标
  └── 安全等级: "默认权限 · 安全沙箱" + L2 Badge
```

**两版输入区布局差异**：
- 版本 A：控制条在输入框上方（两行布局）
- 版本 B：快捷按钮在输入框左侧（单行布局）
- 发送按钮：版本 A 是圆形图标，版本 B 是文字+图标

### 3.3 WorkBuddy 输入区独有特性

| 特性 | 描述 | EcoMind 需要吗？ |
|------|------|----------------|
| **模型选择器** | 支持切换 GLM/MiniMax/Kimi K2.5 等 | 需要 LiteLLM 路由已在后端，前端缺少切换入口 |
| **环境指纹** | 底部显示 Node/npm/Git 版本 | 需要但内容不同——应显示"安全等级/模型/连接器状态" |
| **智能纠偏** | 检测到缺少环境→提供替代方案 | 非常需要——如缺少数据源→提示上传 |
| **快捷模板预填充** | 选择模板→自动填充上下文 | 需要——[环评预检]→自动填充企业信息模板 |
| **文件拖拽/粘贴** | 直接粘贴文件到输入框 | 需要——支持粘贴 Excel/Word 做数据分析 |

### 3.4 设计差距评估

**问题 1：模型选择器缺失**
EcoMind 后端已有 LiteLLM 路由（Qwen3-14B 45% / DeepSeek-671B 28% / Qwen3-72B 18% / GLM-4-9B 9%），但前端无法选择模型。用户无法决定"这个问题用大模型还是小模型"。

**问题 2：环境感知为零**
WorkBuddy 底部有实时环境状态，EcoMind 完全没有。对于政务场景，用户应该看到：
- 当前安全等级（L1/L2/L3）
- 连接器在线状态（监测站点是否可达）
- 模型可用性（LiteLLM 后端是否健康）

**问题 3：输入体验原始**
- 无文件拖拽
- 无粘贴图片识别
- 无快捷模板
- 无上下文感知提示

**建议**：
- 增加 LiteLLM 模型选择器（至少 3 档：快速/标准/深度）
- 底部状态栏：安全等级 + 模型状态 + 连接器状态
- 支持 Excel/Word/PDF 文件拖拽上传
- 增加 4 个政务快捷模板：[环评预检] [水质分析] [合规校验] [应急响应]

## 四、综合差距矩阵

| 区域 | 差距等级 | 核心差距 | 影响范围 |
|------|---------|---------|---------|
| 左边栏 | **中等** | 信息架构过重，缺快捷模板和文件夹分组 | 首次使用体验 |
| 对话框 | **小** | UI 库混用、缺代码高亮、缺文件预览 | 视觉一致性 |
| 右边栏 | **大** | 缺文件预览、缺变更追踪、缺 Agent 状态检测 | 核心使用流程 |
| 输入框 | **大** | 缺模型选择、缺环境感知、缺文件上传 | 每次交互体验 |

### EcoMind 独有优势（WorkBuddy 没有的）

1. **12 专家体系** + 状态指示器
2. **思维链折叠** + 幻觉风险可视化
3. **安全等级标签** (L1/L2/L3)
4. **通知面板** (审批/安全/系统/任务/工作流)
5. **8 种内联组件** (chart/map/table/approval/alert/document/task/image)
6. **参与者头像** (多 Agent 协作可视化)

这些是**政务场景的核心差异化**，不应丢弃，而是在此基础上补齐交互体验短板。
