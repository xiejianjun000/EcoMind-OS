## 三、知识分类框架（5大类）

### 3.1 行业术语与环境

生态环境是一个高度专业化的领域，充满了行话和缩写。AI编码助手需要理解这些术语才能产出正确的代码和文档。

#### 术语表模板

```markdown
## 术语：[术语]

- **全称**：[完整名称]
- **英文**：[English equivalent]
- **定义**：[一句话解释]
- **使用场景**：[在什么上下文中出现]
- **常见误解**：[容易混淆的概念]
- **相关术语**：[关联的其他术语]
```

#### 高优先级术语（建议首批整理）

| 术语 | 全称 | 简述 |
|------|------|------|
| 排污许可 | 排污许可证管理 | 企业合法排放的凭证制度 |
| 环评 | 环境影响评价 | 建设项目开工前的环境影响评估 |
| 国控站 | 国家控制环境质量监测点 | 环保部直接管理的监测站点 |
| 自动监测 | 环境质量自动监测系统 | 24小时连续自动采集数据 |

| 标气 | 标准气体 | 用于校准监测仪器的已知浓度气体 |

### 3.3 边界案例与陷阱

#### 边界案例模板

```markdown
## 案例：[案例标题]

### 背景
[什么场景下发生的]

### 易错点
[大多数人会怎么做（错误的）]

### 正确做法
[应该怎么做（正确的）]

### 代码影响
[这个案例对代码实现有什么影响]
[如果代码没有考虑这个案例，会出现什么问题]

### 关联知识
[相关的法规、术语、流程]
```

#### 示例案例

```markdown
## 案例：监测数据异常不等于排放超标

### 背景
某空气自动监测站PM2.5浓度突然升高到300μg/m³。

### 易错点
系统直接判断为"周边企业排放超标"，触发执法预警。

### 正确做法
先排查非排放因素：
1. 气象因素（逆温、沙尘天气、静稳天气）
2. 设备因素（校准失效、切割器堵塞、采样管路漏气）
3. 人为因素（站点周边施工、洒水车经过）
4. 区域传输（上风向城市污染传输）

排除上述因素后，再触发执法预警。

### 代码影响
- 异常检测模块必须区分"监测值异常"和"排放异常"
- 研判Agent需要获取气象数据作为上下文
- 预警级别应根据置信度分级
```

### 3.4 利益相关者地图

| 角色 | 关注点 | 决策标准 | 沟通方式 |
|------|--------|---------|---------|
| 生态环境局局长 | 政治考核、上级指示、社会影响 | 是否能帮助完成年度考核目标 | 汇报材料、标杆案例 |
| 信息中心主任 | 系统稳定性、安全合规、预算执行 | 是否等保合规、是否与现有系统兼容 | 技术文档、安全评估报告 |
| 执法大队队长 | 案件办理效率、执法覆盖率 | 能否减少重复工作、能否提升执法质量 | 试点效果数据、效率对比 |
| 监测站站长 | 数据质量、设备运行率 | 能否减少人工质控工作量 | 数据准确率、异常检测效果 |
| 一线执法队员 | 工作便利性、学习成本 | 是否真的好用、是否增加额外负担 | 界面易用性、培训成本 |
| 财务科科长 | 预算合规、资金使用效率 | 是否符合采购规定、性价比如何 | 报价方案、同类产品对比 |

## 四、与L4认知记忆层的连接

手册Ch6推荐动作5：*"把用户数据变成产品飞轮：分析用户接受和拒绝的输出、行为模式、长期偏好和边界案例，用它们驱动模型与产品改进。"*

### 知识外化 → L4记忆的映射

| 外化知识 | L4组件 | 存储方式 | 用途 |
|---------|--------|---------|------|
| 行业术语词典 | 知识图谱节点 | Neo4j | Agent理解用户意图 |
| 监管流程知识 | 知识图谱边+规则 | Neo4j + 规则引擎 | Agent执行合规操作 |
| 边界案例集 | 向量数据库 | pgvector | 研判Agent参考历史案例 |
| 利益相关者画像 | 结构化数据 | PostgreSQL | 产品和销售参考 |
| 用户反馈数据 | 向量+结构化 | pgvector + PostgreSQL | 飞轮驱动产品改进 |

### 知识积累飞轮

```
创始人外化知识 → L4记忆层
         ↑                ↓
    知识库维护        用户使用反馈
         ↑                ↓
    领域学习        AI辅助知识提取
```
