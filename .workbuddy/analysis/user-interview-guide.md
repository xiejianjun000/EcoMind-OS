# EcoMind OS 目标用户访谈指南

> 基于《创始人手册》Ch3 推荐动作3（分层梳理竞争格局）、推荐动作4（设计客户访谈）、推荐动作5（每五次访谈后做综合）

---

## 一、访谈目标

**不是验证"EcoMind OS好不好"，而是验证"生态环境从业者是否真的有某个具体问题，以及这个问题有多痛"**。

手册Ch3原文：*"想法阶段的目标不是把产品做出来，而是证明'这个问题真实、具体、频繁'。"*

### 核心验证假设

| 编号 | 假设 | 验证标准 |
|------|------|---------|
| H1 | 环境执法人员日常工作中存在"信息分散、需要跨系统查数据"的痛点 | ≥3/5受访者独立描述类似场景 |
| H2 | 现有系统无法满足"智能预警+自动研判"的需求 | ≥3/5受访者表示现有工具在某个关键场景下不够用 |
| H3 | 目标用户愿意尝试AI辅助工具 | ≥2/5受访者在访谈中主动表达"如果有个东西能..." |
| H4 | 该问题出现频率≥每周1次 | ≥3/5受访者确认 |

## 二、目标用户画像（4个）

### 画像A：一线执法队员

| 属性 | 描述 |
|------|------|
| **典型角色** | 市级/区级生态环境综合执法大队队员 |
| **日常工作** | 现场检查、取证、笔录、处罚建议、案卷整理 |
| **当前工具** | 全国环境行政处罚案件办理系统、省厅执法APP、微信工作群、纸质台账 |
| **可能的痛点** | 现场取证与后台数据脱节、跨部门数据（排污许可+监测+信用）无法一站式查询、重复录入 |
| **决策影响力** | 低（执行层），但能提供最真实的日常痛点 |

### 画像B：环境监测站运维人员

| 属性 | 描述 |
|------|------|
| **典型角色** | 国控/省控空气/水质自动监测站运维工程师 |
| **日常工作** | 设备巡检、数据质控、异常排查、运维报告编写 |
| **当前工具** | 国家环境监测总站平台、设备厂商管理软件、Excel报表 |
| **可能的痛点** | 多品牌设备数据格式不统一、异常数据告警延迟、质控流程手工化、无法快速回溯历史问题 |
| **决策影响力** | 中（技术选型建议权） |

### 画像C：环评编制单位工程师

| 属性 | 描述 |
|------|------|
| **典型角色** | 环评机构项目负责人/工程师 |
| **日常工作** | 现场踏勘、资料收集、模型计算、报告编制、技术评估会应对 |
| **当前工具** | 环评基础数据库、气象/水文数据平台、CAD/GIS、Word/Excel |
| **可能的痛点** | 基础数据收集耗时长、跨部门协调困难、政策更新频繁难追踪、重复性文字工作量大 |
| **决策影响力** | 中（工具采购建议权） |

### 画像D：生态环境局信息中心负责人

| 属性 | 描述 |
|------|------|
| **典型角色** | 市/区生态环境局信息中心主任或信息化分管领导 |
| **日常工作** | 信息化项目管理、系统运维、数据安全管理、新技术评估 |
| **当前工具** | 政务云平台、各业务系统管理后台、运维监控系统 |
| **可能的痛点** | 系统烟囱化严重、数据孤岛打通成本高、安全合规压力大、AI应用需求来自上面但落地路径不清 |
| **决策影响力** | 高（预算审批、系统选型） |

## 三、访谈问题清单（20题，按主题分组）

### 模块一：当前工作流程与痛点（7题）

1. 请描述你最近一周最典型的工作日，从早到晚你做了哪些事？
2. 在这些工作中，哪件事最耗时？哪件事你觉得"不应该花这么多时间"？
3. 你日常需要使用多少个不同的系统/软件/平台来完成工作？请列举。
4. 这些系统之间，数据能互通吗？你有没有因为数据不互通而做过重复工作？
5. 上次你遇到一个棘手的工作问题是什么？你是怎么解决的？花了多长时间？
6. 在你的工作中，有没有某个环节，你觉得"如果有工具能自动做就好了"？请具体描述。
7. 你和同事之间，经常需要通过什么方式协调工作？有没有效率低的地方？

### 模块二：现有工具的使用体验（5题）

8. 你目前最常用的系统是什么？它最让你满意和最不满意的地方分别是什么？
9. 你有没有尝试过使用AI工具（如ChatGPT、文心一言等）辅助工作？效果如何？
10. 如果让你给现有的工作系统打分（1-10），你打几分？扣分的主要原因是什么？
11. 你听说过或接触过其他地区的生态环境信息化系统吗？有没有你觉得做得好的？
12. 你觉得现在市面上的环保类软件/平台，最大的通病是什么？

### 模块三：对AI辅助的期望与顾虑（4题）

13. 如果有一个AI助手能帮你处理工作中的某些任务，你最希望它帮你做什么？（不限制技术）
14. 你对AI在环保领域的应用有什么顾虑？（安全、准确、合规、就业等）
15. 什么样的证据会让你愿意在一个新工具上投入时间学习？
16. 如果这个工具是收费的，你/你的单位愿意为什么样的功能付费？

### 模块四：采购决策流程（4题，仅画像D）

17. 你局里信息化项目的预算通常是怎么审批的？周期多长？
18. 选择信息化供应商时，你最看重的三个因素是什么？
19. 过去三年你们采购过哪些信息化项目？效果如何？
20. 如果一个初创团队想和你们合作试点，你需要看到什么才会同意？

## 四、访谈方法论

### 避免引导性提问

| 错误问法 | 正确问法 |
|---------|---------|
| "你是不是觉得现在的系统很难用？" | "你用现在的系统时，遇到过什么困难吗？" |
| "如果有个AI能帮你自动预警，你觉得好不好？" | "在工作中，有没有什么信息你希望能更早知道？" |
| "你一周需要花多少时间做重复的数据录入？" | "请具体描述一下你处理数据的过程" |

### 识别真实痛点 vs 客套话

- **真实痛点**：受访者主动举例、描述具体场景、表现出情绪（沮丧/无奈/愤怒）
- **客套话**：泛泛而谈"还不错"、"都还行"、没有具体故事支撑
- **追问技巧**：用"能给我讲一个最近发生的具体例子吗？"替代"能详细说说吗？"

### 手册Ch3推荐动作5：每五次访谈做一次综合

| 分析维度 | 记录内容 |
|---------|---------|
| 支持假设的证据 | 列举每位受访者的具体表述和场景 |
| 挑战假设的证据 | 与原假设矛盾的发现 |
| 意外信息 | 访谈中始料未及的需求或洞察 |
| 模式识别 | 多位受访者反复提及的问题 |

## 五、成功标准（Done Definition）

### 什么结论算"验证通过"

- **强验证**：≥4/5受访者独立描述了同一个具体痛点，且频率≥每周1次，现有工具无法解决
- **中验证**：3/5受访者描述了相关痛点，但场景略有差异，需要进一步聚焦
- **弱验证/转向信号**：≤2/5受访者描述了预设痛点，或痛点频率很低（<每月1次），或现有工具已基本满足

### 什么结论算"需要转向"

- 访谈中发现了一个比预设假设更频繁、更痛的新问题 → 围绕新问题重新设计MVP
- 目标用户表示"AI辅助不是我的刚需" → 重新审视产品方向
- 决策层（画像D）表示"预算不可能给新供应商" → 重新评估商业路径
