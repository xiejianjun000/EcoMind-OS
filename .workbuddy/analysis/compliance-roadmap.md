# EcoMind OS 合规路线图

> 基于《创始人手册》Ch5 推荐动作3（"面向目标客户所需标准，准备控制、审计日志、访问管理、文档和独立评估材料"）和Ch5常见风险（"安全与合规不再可推迟：真实用户、真实数据、付款与企业合同意味着风险不再是假设"）

---

## 一、目标合规标准

| 标准 | 适用阶段 | 强制性 | 说明 |
|------|---------|:------:|------|
| **等保二级** | 发布阶段 | 是 | 处理非敏感政务数据的最低要求 |
| **等保三级** | 规模化阶段 | 是 | 处理敏感环保数据的企业级标准 |
| **《数据安全法》** | 发布阶段 | 是 | 数据分类分级、安全评估、跨境传输 |
| **《个人信息保护法》** | 发布阶段 | 是 | 用户数据处理（如登录信息、行为数据） |
| **《网络安全法》** | MVP阶段 | 是 | 网络运营者基本义务 |
| **《生态环境监测网络管理办法》** | 发布阶段 | 是 | 监测数据的采集、传输、存储规范 |
| **政务云安全要求** | 发布阶段 | 视客户 | 部分地方政府要求部署在指定政务云 |

## 二、差距分析：当前设计 vs 合规要求

### 2.1 等保三级差距

| 控制域 | 等保三级要求 | EcoMind OS 当前状态 | 差距 |
|--------|------------|-------------------|------|
| **安全物理环境** | 机房、门禁、监控 | 使用云服务商基础设施（阿里云/华为云） | 依赖云服务商合规认证 |
| **安全通信网络** | 网络架构、边界防护、入侵防范 | 未部署 | 需配置WAF、IDS、网络隔离 |
| **安全区域边界** | 访问控制、入侵防范、恶意代码防范 | 基础认证（API Key） | 需增强：RBAC、IP白名单 |
| **安全计算环境** | 身份鉴别、访问控制、安全审计、数据完整性 | L1/L2/L3三级安全设计（理念级） | 需实现：审计日志、数据加密、密码策略 |
| **安全管理中心** | 系统管理、审计管理、安全管理 | 无 | 需建设：集中日志、安全事件管理 |
| **安全管理制度** | 安全策略、管理制度、操作规程 | 无 | 需编写全套安全管理制度文档 |

### 2.2 《数据安全法》差距

| 要求 | 当前状态 | 差距 |
|------|---------|------|
| 数据分类分级 | 未定义 | 需制定数据分类分级标准 |
| 数据安全评估 | 未开展 | 处理重要数据前需做安全评估 |
| 数据加密 | 未实现 | 传输加密(TLS)和存储加密需实现 |
| 数据备份 | 未实现 | 需配置定期备份和恢复方案 |
| 数据出境 | 不涉及 | MVP阶段无跨境需求 |

### 2.3 《个人信息保护法》差距

| 要求 | 当前状态 | 差距 |
|------|---------|------|
| 隐私政策 | 无 | 需编写并公示 |
| 最小必要原则 | 未评估 | 需评估数据收集范围 |
| 用户权利（删除/更正） | 未实现 | 需提供数据导出和删除功能 |
| 同意机制 | 无 | 注册时需明确同意 |

## 三、分阶段合规计划

### Phase 1：MVP阶段（Month 1-3）—— 基础安全

> 手册Ch4推荐动作4：*"上线前做安全评审：重点检查鉴权与会话、API数据暴露、输入校验与注入、依赖漏洞，以及所有涉及秘密和用户数据的路径。"*

| 控制措施 | 优先级 | 实现方式 | 预计工时 |
|---------|:------:|---------|:--------:|
| HTTPS全站加密 | P0 | Nginx TLS证书 | 2小时 |
| 基础认证（JWT） | P0 | FastAPI + PyJWT | 4小时 |
| API输入校验 | P0 | Pydantic模型验证 | 8小时 |
| 环境变量管理 | P0 | .env + Docker Secrets | 2小时 |
| 依赖漏洞扫描 | P0 | pip-audit / safety | 持续 |
| 基础审计日志 | P1 | Python logging → 文件 | 4小时 |
| CORS策略 | P1 | FastAPI中间件 | 1小时 |
| Rate Limiting | P1 | slowapi | 2小时 |
| 数据库备份 | P1 | pg_dump定时任务 | 2小时 |

**阶段里程碑**：通过基础安全自检清单，可安全部署到公网供试点用户使用。

### Phase 2：发布阶段（Month 4-6）—— 等保二级

| 控制措施 | 优先级 | 实现方式 | 预计工时 |
|---------|:------:|---------|:--------:|
| RBAC权限管理 | P0 | 自研 + FastAPI依赖注入 | 16小时 |
| 操作审计日志（完整） | P0 | 结构化日志 → PostgreSQL | 8小时 |
| 数据分类分级标准 | P0 | 文档 + 代码标注 | 8小时 |
| 敏感数据加密存储 | P0 | AES-256（数据库字段级） | 8小时 |
| 密码策略 | P1 | 最小长度、复杂度、过期策略 | 4小时 |
| 会话管理 | P1 | Token过期、单点登录控制 | 4小时 |
| 安全事件响应流程 | P1 | 文档 | 4小时 |
| 渗透测试 | P0 | 第三方安全公司 | 外包 |
| 等保二级测评 | P0 | 指定测评机构 | 外包 |
| 隐私政策 | P1 | 法律顾问审核 | 外包 |
| 安全管理制度文档 | P0 | 安全管理制度、操作规程、应急预案 | 16小时 |

**阶段里程碑**：通过等保二级测评，具备面向政府客户交付的基本条件。

### Phase 3：规模化阶段（Month 7-12）—— 等保三级

| 控制措施 | 优先级 | 实现方式 | 预计工时 |
|---------|:------:|---------|:--------:|
| 网络隔离 | P0 | VPC + 安全组 + 私有网络 | 云配置 |
| WAF部署 | P0 | 云WAF服务 | 云配置 |
| IDS/IPS | P0 | 云安全中心 | 云配置 |
| 集中安全管理 | P0 | SIEM（如阿里云SLS安全中心） | 16小时 |
| 数据安全评估 | P0 | 自评 + 第三方评估 | 外包 |
| 等保三级测评 | P0 | 指定测评机构 | 外包 |
| 灾备方案 | P1 | 异地备份 + 演练 | 16小时 |
| 安全培训 | P1 | 团队安全意识培训 | 定期 |
| 供应链安全 | P1 | 开源依赖License扫描 + SBOM | 持续 |

**阶段里程碑**：通过等保三级测评，具备参与大型政府项目投标的资质条件。

## 四、等保测评预估费用

| 项目 | 等保二级 | 等保三级 |
|------|:-------:|:-------:|
| 测评费用 | 5-8万 | 10-15万 |
| 整改配合 | 3-5万（自研为主） | 10-20万（需外部协助） |
| 安全设备/服务 | 2-3万/年 | 10-20万/年 |
| **合计** | **10-16万** | **30-55万** |

## 五、合规风险矩阵

| 风险 | 概率 | 影响 | 缓解措施 |
|------|:----:|:----:|---------|
| 等保测评不通过 | 中 | 高 | 提前3个月启动整改，预留缓冲期 |
| 数据泄露事件 | 低 | 极高 | 加密存储+传输+审计日志+响应预案 |
| 开源组件License不合规 | 中 | 中 | 定期扫描（FOSSA/license-checker） |
| 用户隐私投诉 | 低 | 中 | 隐私政策+最小必要原则+用户权利功能 |
| 政务云不开放 | 中 | 高 | 提前与云服务商和客户沟通 |
